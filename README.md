# シフト作成ツール

薬局のスタッフのシフト表を作るツールです。医師の出勤人数から必要な薬剤師の人数を出し、
希望休を守りながら、早番・遅番・遅半をスタッフのあいだで均等に配ります。

## 使い方

**[`ShiftGenerator.html`](ShiftGenerator.html) 1つで動きます。** インストールもインターネットも要りません。

1. [`ShiftGenerator.html`](ShiftGenerator.html) を開き、右上の **ダウンロードのボタン（Download raw file）** で保存する
   （[リリース](https://github.com/Sekine53629/ShiftGenerator/releases/latest) の zip にも入っています）
2. 好きなフォルダ（たとえば `ドキュメント\ShiftGenerator`）に置き、**Microsoft Edge か Google Chrome** で開く
3. 画面の **「保存先フォルダを選ぶ（初回だけ）」** で、HTML を置いたフォルダを選ぶ。
   マスタは `data\db.json`、シフトは `data\cells\2026-11.json` のように月ごとに保存されます
4. **社員マスタ**・**医師マスタ**に人を入れ、年月を選んで医師名の欄を埋める
5. 希望休・有休を入れてから **「自動生成」** を押す

手で入れたセル（希望休・有休・手で置いたシフト）は緑の文字で出て、自動生成で書き換わりません。
表の下に「確認が要るところ」（週の勤務日数・連勤・早番と遅番の人数など）が出ます。
月ができあがったら **「月を確定」** を押すと、次に開いたときは翌月から始まります。

| 出力 | |
|---|---|
| **PDF** | 印刷画面で「PDF に保存」。A4 横 1 枚に収まります |
| **スプレッドシート** | `.xlsx` で保存。集計（公休・早番の回数・過不足など）は数式で入ります |

PDF と Excel の色は **「出力の色」タブ** で変えられます。
データは選んだフォルダの中だけにあり、どこにも送られません。フォルダごと控えを取れば、別のパソコンへも移せます。

## ローカルで使う（この PC の中だけで動かす）

サーバ（Google Apps Script）を使わず、1台の PC で使うときの置き方。

1. `tools\install-local.ps1` を実行する

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\tools\install-local.ps1
   ```

   - `ドキュメント\ShiftGenerator\` と、その下の `data\` を作る
   - `prototype\ShiftGrid.html` を `ShiftGenerator\ShiftGenerator.html` として置く
   - デスクトップに「シフト作成」のショートカットを作る（Edge で開く）
   - **`data\` の中身には触らない。** HTML を新しくするときも、これをもう一度実行するだけ

2. ショートカットから開き、画面上部の **「保存先フォルダを選ぶ（初回だけ）」** で
   `ドキュメント\ShiftGenerator` を選ぶ

   - マスタ・設定は `data\db.json`、シフトは **月ごとに** `data\cells\2026-11.json` のように保存される（**こちらが正**）。
     直した月のファイルだけを書き直すので、何年分たまっても重くならない
   - 前の形（`data\cells.json` 1つに全部の月）を見つけたら、月ごとに分けて書き直し、元は `cells.json.bak` で残す
   - 選んだフォルダはブラウザが覚える。次からは「保存先フォルダに接続」を1回押すだけ
     （ブラウザの設定によっては、それも要らない）
   - この機能は **Edge と Chrome だけ**で動く（File System Access API）。
     ほかのブラウザでは、これまでどおりブラウザの中にだけ保存する

月のシフトができたら **「この月を確定」** を押す。次に開いたときは、その翌月から始まる。
確定したあとも、前の月は年月を選び直せば直せる。

### 前の版（配布版 1.0〜1.2.1 の `シフト表エディタ.html`）から移る

前の版のマスタ・シフトは**ブラウザの中**にあり、新しい版も同じ場所を読む。
**同じパソコンの同じブラウザ（現場は Edge）で開けば、そのまま出る。**

1. 念のため、前の版の「データ書き出し」で控えを取り、`.json` で保存しておく
2. `tools\install-local.ps1` を実行する（ショートカットは Edge で開く。Chrome の店は `-Browser Chrome`）
3. ショートカットから開き、社員・医師・シフトが出ていることを確かめる
   - **空に見えたら、いつもと違うブラウザで開いている**（データはブラウザごとに別）。
     いつものブラウザで開くか、1 の控えを「データ書き出し」タブに貼って「取り込む」
4. **事務員と、雇用「派遣」の人は、勤務ルールが一度だけ「手動」に切り替わる**。
   自動で組みたい人は、社員マスタで勤務ルールを「通常」などに戻す
5. 「保存先フォルダを選ぶ（初回だけ）」では **空のフォルダ**（`ドキュメント\ShiftGenerator`）を選ぶ。
   いまの中身がそこへ書かれる。すでにデータのあるフォルダを選ぶと、そちらの中身で始まる

新しい版は、前の版のデータを直す前の中身を、ブラウザの中に一度だけ控える
（`shiftgrid.db.v1.before-v3`）。万一のときは、その中身を「取り込む」で戻せる。

### 配布用の zip を作る

```
node tools/make-package.js
```

`dist/AutoShiftGenerator-<版>.zip` ができる（版は `ShiftGrid.html` の `APP_VERSION`）。
中身は `ShiftGenerator.html`・`install-local.ps1`・`README.md`（`tools/package/README.md` が元）。
zip を展開して `install-local.ps1` を実行すれば、上と同じ置き方になる。

**公開の前に、実名が入っていないことを確かめる。** 医師名・社員名は、例やテストでも
明らかに架空の名前（`甲野 太郎`・`薬剤師 A` など）にする。

## セットアップ

### 1. スクリプトを貼る

1. シフト表用のスプレッドシートを開き、**拡張機能 → Apps Script**
2. 左の **⚙ プロジェクトの設定** → 「**`appsscript.json` マニフェスト ファイルをエディタで表示する**」にチェック
   （`appsscript.json` は「＋」から追加できません。最初から在るファイルを表示させて中身を差し替えます）
3. リポジトリ直下の `.gs` と `WebAppView.html` を貼る。`appsscript.json` は中身を置き換える
   - **`archive/` の中身は貼らないでください。** 名前が衝突します（「構成」の注意を参照）
   - `clasp` を使う場合、`.clasp.json` は `.gitignore` 済みです

`appsscript.json` の `webapp` ブロックは、デプロイ時のダイアログで選んだ値に上書きされるので
貼らなくても構いません。

#### 要求する権限

`oauthScopes` を**明示しているので、書いていない権限は要求されません**。
足りないと、その API を呼んだ時点で失敗します。機能を足すときは必ずここも見直してください。

| スコープ | 何に使うか |
|---|---|
| `spreadsheets.currentonly` | このスクリプトが紐づくスプレッドシートだけを読み書きする |
| `script.container.ui` | メニュー・ダイアログ・Web アプリの画面 |
| `script.external_request` | 内閣府の祝日 CSV を取る（`Holidays.gs`） |
| `script.send_mail` | 致命的エラーを管理者へ通知する（`Log.gs`） |
| `userinfo.email` | 通知先が未設定のときに実行ユーザーのアドレスを使う（`Log.gs`） |

PDF 出力（フェーズ7）を実装するときに Drive のスコープを足します。
仕様書 §2 の一覧は先取りで `drive.readonly` を含んでいますが、**まだ誰も使っていない**ので外してあります。

初回実行時に「**このアプリは Google で確認されていません**」と出ます。
自分で書いたスクリプトを自分のスプレッドシートで動かす限り正常な表示です
（確認は一般公開するアプリに要るもの）。
**詳細を表示 → （安全ではないページ）に移動 → 許可** で進めます。

### 1-b. clasp で送る（手貼りの代わり。推奨）

16 ファイルを手で貼ると、貼り先を間違えたり打鍵が紛れたりします。
`.gs` は全ファイルで1つのグローバルスコープを共有するので、
**1ファイルの事故でプロジェクト全体が止まります**。`clasp` ならその事故が起きません。

```bash
npm i -g @google/clasp
clasp login                       # ブラウザが開くので Google アカウントで許可
```

**Apps Script API を有効にしておくこと。** <https://script.google.com/home/usersettings> で
「Google Apps Script API」をオンにします。これを忘れると `clasp push` が
「User has not enabled the Apps Script API」で必ず失敗します。

次に、**スクリプト ID を調べて `.clasp.json` を自分で作ります**。
ID は Apps Script エディタの **⚙ プロジェクトの設定 → スクリプト ID** にあります。

```bash
# リポジトリのルートで
cat > .clasp.json <<'EOF'
{ "scriptId": "ここにスクリプトID", "rootDir": "." }
EOF

clasp push --force
```

`.clasp.json` は `.gitignore` 済みなので、コミットされません（別のパソコンでは作り直します）。

> **`scriptId` はスプレッドシート ID ではありません。** 別物です。
> スプレッドシート ID は URL の `.../spreadsheets/d/＜ここ＞/edit`、
> スクリプト ID は Apps Script エディタの **⚙ プロジェクトの設定 → スクリプト ID**。
> コンテナバインドのスクリプトは、スプレッドシートに紐づいた別の実体です。

#### 複数のブックを使い分ける

`clasp push` に「プロジェクトを指定する」オプションはありません。
切り替えは `.clasp.json` を差し替えます。`.clasp.*.json` も `.gitignore` 済みなので、
環境ごとに置いておいて必要なほうをコピーするのが楽です。

```powershell
# 用意しておく（どちらも git に載りません）
#   .clasp.dev.json   … 練習用のブック
#   .clasp.work.json  … 職場のブック

Copy-Item .clasp.work.json .clasp.json -Force
clasp push --force
```

職場アカウントのブックへ入れるときは、`clasp login` をそのアカウントでやり直し、
**そのアカウント側でも** <https://script.google.com/home/usersettings> の
Apps Script API をオンにします。組織のポリシーで Apps Script API や
外部リクエストが止められている場合は、管理者に開けてもらう以外に手がありません。

> **`clasp clone` は使わないでください。** リモートの中身をローカルへ上書きするので、
> 手貼りで壊れた状態を取り込んでしまいます。ここでは常に
> **ローカル → リモート**の一方向（`clasp push`）で運用します。

`clasp push` は**リモートをローカルの内容に合わせます**。ローカルに無いファイルは
リモートから消えるので、貼り間違えた `Setup` や、旧 `WebApp.html` /
`Sidebar.*` が残っていても、これで一掃されます。

送るものは [`.claspignore`](.claspignore) で決めています。
直下の `.gs` と `WebAppView.html` と `appsscript.json` だけで、
`archive/` `tests/` `docs/` は送りません。

### 2. スクリプトプロパティ（任意）

**プロジェクトの設定 → スクリプト プロパティ**。未設定でも動きます。

| キー | 内容 | 未設定のとき |
|---|---|---|
| `ADMIN_EMAIL` | 致命的エラーの通知先 | 実行ユーザー宛 |
| `EXPORT_FOLDER_ID` | PDF の保存先フォルダ ID | マイドライブ直下 |

メールアドレスやフォルダ ID はコードに書きません（Tier 1 / Tier 2 のルール）。

### 3. シートを用意する

スプレッドシートを開き直すと「**シフト**」メニューが出ます。

1. **初期設定 → 不足シートを生成**
   `自動作成設定` / `祝日マスタ` / `シフト変更ログ` のうち無いものを作ります。
   すでにあるシートには見出しと入力規則を補うだけで、**データには触りません**。
2. **初期設定 → 祝日マスタを取り込む**
   内閣府の CSV から取り直します。日付は必ず日付型で入ります。
3. **`自動作成設定` にメンバーを登録**
   - **A列 氏名**（シフト表の A 列と完全一致させること）と **B列 区分**（`薬剤師` / `事務員`）が必須
   - C〜I 列（休業・勤務ルール・固定曜日・週勤務日数・月間休日数・遅番可否）は自動作成で効きます
   - **N列 医師名**は Web アプリの医師名スタンプの候補になります
   - K/L 列の全体設定は既定値が入っています。変えたい行だけ書き換えてください
4. **（推奨）実物の書式を取り込む** — 下の「書式プロファイル」を参照
5. **初期設定 → シフト表シートを生成** → 年月を入力（例 `2026/9`）

### 4. Web アプリを開く（任意）

Apps Script エディタ → **デプロイ → 新しいデプロイ → 種類「ウェブアプリ」**。
「次のユーザーとして実行: **アクセスしているユーザー**」「アクセスできるユーザー: **自分のみ**」を選びます。

デプロイ後、スプレッドシートの **「シフト」→「Web アプリを開く」**で開けます。

> **⚠ `clasp push` だけでは Web アプリは新しくなりません。**
> デプロイ済みの URL は**デプロイ時点のバージョン**を動かし続けます。
> メニューからの操作は最新コードで動くので、**Web アプリだけが古いまま**という
> 状態になり、「直したのに反映されない」の原因になります。
>
> 更新: **デプロイを管理 → 鉛筆アイコン → バージョン「新バージョン」→ デプロイ**
> （URL は変わりません）
>
> 開発中は「**デプロイをテスト**」の URL を使うと常に最新が動きます。
>
> 画面の右上に**版**（`CONFIG.APP_VERSION`）が出ます。
> 手元のコードと違えばデプロイが古いということです。

### Web アプリ

シフト表をブラウザ上のグリッドで表示し、スタンプで入力して保存できます。
月ごとのシートを切り替えられ、新しい月のシートもここから作れます。

**公開範囲の既定は `MYSELF`（開発者本人のみ）です。**
スタッフにも使わせるなら広げる判断が要りますが、
`executeAs` の選び方で意味がまったく変わります。詳しくは
[`docs/WEBAPP-DESIGN.md`](docs/WEBAPP-DESIGN.md) の「デプロイと公開範囲」を読んでください。
**いまのコードに「誰が編集してよいか」の守りはありません。**

できないこと（実装フェーズ待ち）: 自動作成の実行 / 変更ログへの記録 / PDF 出力 / 背景色 / 月送り。

**押せる場所は制限されます**（仕様書 §6.3）。シフト記号は入力欄だけ、医師名は医師名欄だけ、
備考行と自由行は自由記入、消去はどこでも可。判定はサーバ側（`stampRejectReason_`）が
値そのものを見て行い、画面のボタンの出し分けは見た目の親切でしかありません。
記号が医師名欄に1つ紛れ込むだけで `医師数(診)`（その欄の `COUNTA`）が水増しされ、
必要数と過不足が月まるごと狂うためです。

> **同時編集に強くありません。** 保存は編集の外接矩形をまるごと書き戻すので、
> 読んでから保存するまでのあいだに他の人が同じ範囲を直していると上書きします。

### 書式プロファイル — 実物の見た目で生成する

仕様書はシートの**構造**（どの行に何があるか）は決めていますが、
色・行の高さ・文字サイズといった**見た目**は決めていません。
そこで、運用中のシフト表から測って持っておき、生成時にそれを再現します。

取り込み方は2通りあります。**Excel が手元にあるなら B のほうが正確です。**

#### A. Google スプレッドシート上のシートから取り込む

1. 運用中のシフト表を、このスプレッドシートに取り込む
   （ファイル → インポート → アップロード、または既存シートをコピー）
2. **そのシートを開いた状態で** シフト → 初期設定 → **実物の書式を取り込む**

手軽ですが、**Excel → Sheets の変換で落ちたものは取り戻せません**。
条件付き書式の数式や一部の書式は、取り込みの時点で失われることがあります。

#### 移行の前に: レイアウト診断（Excel 側）

シフト表がまだ Excel にある間は、GAS 側の「レイアウト診断」を走らせられません。
Excel 上で先に「GAS 版がこのシートを読めるか」を確かめられます。

1. シフト表の Excel ブックを開く
2. VBE（Alt+F11）→ ファイル → ファイルのインポート →
   [`tools/DiagnoseLayout.bas`](tools/DiagnoseLayout.bas)
3. 診断したいシートを選んだ状態で `GASProfile_レイアウト診断` を実行
4. 「レイアウト診断」シートの A 列をコピー

見るのは4つです。

| | |
|---|---|
| B列の中身 | 日付行の「1」が**日付なのかただの数値なのか**。画面では見分けが付きません |
| 解決した位置 | 日付行・備考行・集計行・入力欄がどこと判定されたか |
| **GAS 側の定数との整合** | 行の間隔（`医師数行 = 備考行 + 2` など）が合っているか |
| 判定 | 読めるかどうかと、読めない原因 |

**氏名・医師名は伏せます。**型と文字数だけを出し、シフト記号のように
伏せる必要のないものだけ見せます。

#### B. Excel から直接書き出す（推奨）

変換で失われる前の値を Excel 側で測ります。

1. シフト表の Excel ブックを開く
2. VBE（Alt+F11）→ ファイル → ファイルのインポート →
   [`tools/ExportFormatProfile.bas`](tools/ExportFormatProfile.bas)
3. シフト表のシートを選んだ状態で `GASProfile_書式エクスポート` を実行
4. 「GAS書式JSON」シートの **A1 の中身をすべて**コピー
5. GAS 側で シフト → 初期設定 → **書式プロファイルを読み込む（Excel から）** に貼る

`ExportFormatProfile.bas` は移行用のツールで、VBA 版のソース
（`Auto_Shift_Generator/src`）には追加しません。GAS 版の `tools/` に置いてあります。

**単位と色は変換しています。** Excel の行の高さ・列幅は「ポイント」、
Sheets は「ピクセル」なので 4/3 倍します。色は Excel が BGR の数値、
Sheets が `#RRGGBB` なので並べ替えます。ここを間違えると、
エラーは出ないまま違う見た目になります。

**表示形式は書き出しません。** Excel の和暦書式（`[$-ja-JP]ge"." m"月"`）は
Sheets に存在せず、そのまま渡すと壊れるためです（仕様書 §5.2）。
元が何だったかは `_excelMonthFormat` として控えシートに残るので、
下の和暦見出しを合わせるときの手がかりになります。

#### 和暦の見出し

**Sheets に和暦の「表示形式」はありません。** 年月セルを R08.08 と表示させることは
できません。ただし**同じ文字列を数式で作ることはできる**ので、そちらでやります。
毎月手で入力する必要はありません。

年月セル（A列）は**日付のまま**置きます。祝日サマリー・条件付き書式・日付行が
すべて A 列を参照しているので、ここを文字列にすると全部が壊れます。
和暦は別のセル（既定は D 列）に出します。

プロファイルの `title.formula` がその中身です。`{month}` が年月セルの参照に置き換わります。

```
既定: ="R"&TEXT(YEAR({month})-2018,"00")&"."&TEXT(MONTH({month}),"00")
出力: R08.08
```

- 置き場所を変えるなら `title.col`（1=A / 4=D）
- 書式を変えるなら `title.formula` を直して「書式プロファイルを反映」
- **空にすると何も書きません。**手で入力したい場合はそうしてください
- `-2018` は令和固有です。**元号が変わったらここを直します**（自動追従はできません）

**元のシフト表は読むだけで、書き換えません。** 本番のシートを開いたまま実行して安全です。

#### 置き場は「スクリプトプロパティ」

環境ごとの設定なので、GAS で `.env` に相当する**スクリプトプロパティ**
（`FORMAT_PROFILE`）に JSON 1件で持ちます。`ADMIN_EMAIL` などと同じ置き場で、
利用者が誤って壊せません。**生成が読むのはここだけです。**

`書式プロファイル` シートは**控えと手直し用**です。中身を人が読めるように書き出してあり、
値を直せますが、**直しただけでは効きません**。

```
取り込み : 実物のシート ──▶ スクリプトプロパティ（正）─┬─▶ 控えシート
手直し   : 控えシート ──「書式プロファイルを反映」──▶ スクリプトプロパティ（正）
生成     : スクリプトプロパティ（正）──▶ 新しいシフト表
```

手で直したら **初期設定 → 書式プロファイルを反映** を実行してください。
2か所を同時に正にすると、どちらが効いているのか分からなくなるので、
反映は明示的な一手にしてあります。

**何を取り、何を取らないか**

| | |
|---|---|
| 取る | 行の高さ / 背景色 / 文字色 / 文字サイズ / 太字 / 横位置（行の役割ごと）、列幅、土日祝と月外の色、日付と年月の表示形式、集計行と集計列の見出し |
| **取らない** | **セルの中身**。氏名・医師名・面談日程・シフト記号は対象外 |

**条件付き書式で色分けしているシートにも対応しています。**
`getBackgrounds()` は**セルに直接設定された色しか返さず**、条件付き書式で付いた色は
下地（たいてい白）が返ります。そのままだと実物が条件付き書式で土日を色分けしている場合に
プロファイルが真っ白になり、しかもエラーが出ません。
そこで条件付き書式のルール側からも色を読み、静的な色が白／未設定ならそちらを採ります。

見つけた条件付き書式は**使わなかったものも含めて全部**、控えシートの末尾に
数式ごと並べます。担当者の色分けのような曜日と無関係なルールは引き継ぎませんが、
**引き継がなかったこと自体が見える**ようにするためです。

**位置ではなく「行の役割」で持ちます。** セル位置ごとに丸写しすると、
スタッフが1人増えただけで全部ずれますし、丸写しは個人情報まで持ち出すことになります。
`日付行の背景色` `入力欄の文字サイズ` という単位なら、行数が変わっても来年の表にも効きます。

プロファイルはリポジトリには入れません（環境ごとの設定のため）。
空欄にすればその項目だけ既定値に戻ります。知らないキー・壊れた値・壊れた JSON は
捨てて既定値に落ちるので、触っても壊れません。
**書式が読めないせいでシフト表そのものが作れなくなるのは割に合わない**ので、
迷ったら生成できる側に倒しています。

取り込む前でも既定値で生成できます（[`Config.gs`](Config.gs) の `FORMAT_DEFAULT`）。

### シフト表シートの生成

`初期設定 → シフト表シートを生成` で、日付・曜日・医師名欄・入力欄・備考行・
集計行・集計列・区分の作業列・条件付き書式まで入った1か月分のシートを作ります。

- 書式は `書式プロファイル` に従います（未取り込みなら既定値）
- シート名は `2026年9月` のように月ごとに分かれます
- **氏名は自動作成設定シートから読むだけ**で、コードには一切書きません。
  未登録なら空行が並びます
- 医師名欄も空で作ります（候補の置き場は自動作成設定の N 列）
- 月の日数より列が多い分（30 日の月の 31 列目など）は灰色になります
- **月別シートには名前付き範囲を貼りません**。名前はブック全体で一意なので
  12 か月分に同じ名前は付けられないためです。位置は `Layout.gs` が計算で解決するので
  名前が無くても動きます

### マスタの構成

```
自動作成設定（従業員マスタ）  A〜I = 氏名・区分・休業・勤務ルール…
                              K〜L = 全体設定
医師マスタ                    医師名・略称・表示順・備考
シフトパターン                記号・名称・時間帯・種別（出勤/休み）・表示順
備考マスタ                    備考・説明・表示順（銀行など）
祝日マスタ                    日付・名称
```

**備考はシフトパターンに混ぜません。** 銀行はシフトのパターンではなく、
混ぜると `開始` `終了` の列が意味を持たない行ができて、
シフトパターンというシートの意味自体が曖昧になります。

**従業員マスタは `自動作成設定` の A〜I 列がそれです。**別シートに切り出して
いません。シート名と列位置を Layout・エンジン・数式が参照していて、
移し替えると影響範囲が広いためです。移植が固まってから検討します。

**ノルマ対象/外は `シフトパターン` に持ちません。**
休み記号がノルマを食うかは `自動作成設定` L列「ノルマ外の休み記号」が正です。
両方に持つと二重管理になり、どちらが効いているのか分からなくなります。

### 使うシート

| シート | 役割 | 作り方 |
|---|---|---|
| `医師マスタ` | 医師名・略称・表示順 | 初期設定 → 不足シートを生成 |
| `シフトパターン` | 記号・名称・時間帯・種別（出勤/休み） | 同上 |
| `備考マスタ` | 備考行に押す文字（銀行など） | 同上 |
| `書式プロファイル` | 書式の寸法の**控え**（正はスクリプトプロパティ） | 初期設定 → 実物の書式を取り込む |
| `2026年9月` など | シフト表（月ごと） | 初期設定 → シフト表シートを生成 |
| `自動作成設定` | メンバー・全体設定・医師名リスト | 初期設定 → 不足シートを生成 |
| `祝日マスタ` | 祝日の日付と名称 | 初期設定 → 祝日マスタを取り込む |
| `シフト変更ログ` | 変更履歴（フェーズ5で使う） | 初期設定 → 不足シートを生成 |
| `実行ログ` | エラーと正常終了の記録 | 自動で作られる |

生成は**空欄のセルにしか書かない**ので、既存の値が消えることはありません。
何度実行しても壊れません。

## VBA 版から落ちた機能・変わった挙動

移植で意図的に落としたもの、GAS 側の制約で変わったものです。

| 項目 | VBA 版 | GAS 版 |
|---|---|---|
| シート上のパレット3行 | ★マーカー行 / 本体行 / ラベル行 | **生成しない**。サイドバーが引き継ぐ |
| ダブルクリックで記号を順送り | あり | サイドバーの「次へ ▶」 |
| 右クリックで1つ戻す | あり | サイドバーの「◀ 前へ」 |
| 範囲を選んで右クリックで一括 | あり | 範囲を選んでサイドバーのボタン |
| 和暦の表示形式 | `[$-ja-JP]ge"." m"月"`（元号に自動追従） | **表示形式としては不可能**。年月セルは日付のまま置き、和暦は別セルに数式で組む（`title.formula`）。**元号が変わったら数式を直す必要がある** |
| 月送りのスピンボタン | Forms コントロール | サイドバーの「◀ 前月 / 翌月 ▶」 |
| Excel(.xlsx) 出力 | あり | PDF のみ（必要なら同じ URL の `format=xlsx`） |
| エラー行番号 `Erl` | あり | `error.stack` |
| エラーログの出力先 | `C:\VBAErrorLogs\*.csv` | `console` + `実行ログ` シート + 管理者メール |
| 祝日の取込 | Power Query（Excel 2016 以降） | `UrlFetchApp`（バージョン制限なし） |
| 手動変更のログ | `Worksheet_Change` で全編集を捕捉 | **Web アプリ経由の変更のみ**（未実装）。セル直接編集は残らない |
| クリック入力の場所 | シート上のパレット行 | **Web アプリの独自グリッド**（サイドバーは従） |
| 出勤記号の判定 | 完全一致（`○` `◯` `●` `▲`） | **先頭一致**。派遣行の「▲＋氏名」を出勤として数えるため |

### 追加した制限（VBA 版に無いもの）

- **`CB_2名移す` の打ち切り `CB_CHAIN_MAX_PASS = 50`**
  （[`Config.gs`](Config.gs) の `ENGINE_LIMIT`）

  `CoverBalance` は最大 500 巡回りますが、その全部が玉突き（2名移す）に落ちると
  約 60 億ステップになり、GAS の 6 分制限（一般アカウント）を確実に超えます。
  VBA 版にはこの制限がありません。移植の突き合わせで差が出たらまずここを疑ってください。

- **出勤記号の先頭一致 `WORK_SYM_PREFIX_MATCH = true`**（[`Config.gs`](Config.gs)）

  実物のシフト表では派遣行に「▲＋氏名」が1つのセルに入っています。VBA 版は完全一致でしか
  出勤を数えないので、これらは休みと分類され、薬剤師出勤数にも入らず、
  **派遣が出ている日を「人が足りない日」と誤判定**していました。
  先頭一致にして頭数へ入れています（配置は別で、派遣行は勤務ルールを「手動」にします）。

  **移植の突き合わせ検証（仕様書 §9 フェーズ3）では `false` に戻して比べてください。**

### 名前付き範囲の扱い

Sheets の名前付き範囲は**数式を持てず、範囲アドレスしか持てません**。
VBA 版は `OFFSET` / `INDEX` の相対参照だったため行の増減に追随しましたが、
GAS 版は貼り直すまで古いままになります。

そのため **`Layout.gs` の計算解決を正**とし、名前付き範囲は利用者向けの目印
という位置づけです。両者のずれは「設定チェック」が警告します。
