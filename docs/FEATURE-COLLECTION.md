# 特徴量の収集設計

需要予測・BI のための観測データをどう溜めるか。**予測モデルを作る前に器を用意する**
ための設計。モデルが無くても収集は始められるし、始めておかないと学習データが貯まらない。

> 因果の向きは [DEMAND-FORECAST-CONCEPT.md](DEMAND-FORECAST-CONCEPT.md) を参照。
> 潜在患者数 → 予約数 → 医師数 → 必要人数。医師数は結果として現れる指標。

---

## 1. まず決めること — 何を予測するのか

目的変数が決まらないと特徴量の良し悪しが判定できない。段階を踏む。

| 段階 | 目的変数 | 取りやすさ | 使い道 |
|---|---|---|---|
| **第1段階** | **処方箋枚数** | いま取れる（日誌） | 忙しさの代理指標 |
| 第2段階 | 処方箋枚数 × 手間係数 | 手間の内訳を採り始めれば | 工数に近い |
| 第3段階 | 実工数（分） | 計測の仕組みが要る | 直接の必要人数 |

**第1段階から始める。** 枚数だけでも、曜日・医師数・連休明けの効果は見える。

### 手間係数は当てずっぽうで決めない

第2段階の「手間係数」を、こちらで数値として置くことはしない。
**加算の件数と、その日の投入人数（人数×勤務時間）を並べて溜めれば、係数は回帰で
推定できる。** 1件あたり何分かをストップウォッチで測る必要はないし、
測った値より実データから出した値のほうが実態に合う。

```
その日の工数 ≒ a×処方箋枚数 + b×一包化 + c×計量混合 + d×自家製剤 + e×重複 + …
```

`a`〜`e` をデータから求める。**そのために必要なのは、加算の件数を日次で
溜めておくことだけ。** 溜まっていなければ何年経っても推定できない。

**注意**: 必要人数を直接の目的変数にしてはいけない。過去の必要人数は「そのとき組めた
人数」であって「本当に要った人数」ではない。忙しさを予測し、人数はそこから決める。

## 2. 特徴量の棚卸し

### A. すでに挙がっているもの

| 特徴量 | 出どころ | 粒度 | 状態 |
|---|---|---|---|
| 処方箋枚数 | 業務日誌 | 日 | **取れている** |
| 医師出勤数 | シフト表 | 日 | **取れている**（この画面） |
| 曜日 | 暦 | 日 | 計算で出る |
| 祝日 | 暦 | 日 | 計算で出る（振替・国民の休日も） |
| 室温・湿度 | 日誌（湿度計） | 日 | **取れている** |
| 天候 | 気象庁のオープンデータ | 日 | 取りに行けば取れる |
| 処方箋予約情報 | 予約システム | 日 | 連携が要る |
| 最寄り駅からの位置 | 静的 | 店舗 | 一度入れれば済む |
| 処方せん内の最大処方日数 | レセコン | 処方箋 | 集計が要る |

### B. 足りないもので、いま取れそうなもの

**計算だけで出る（コストゼロ・今日から使える）**

| 特徴量 | なぜ効くか |
|---|---|
| **前日が休診か／翌日が休診か** | 連休明けは跳ね、連休前は前倒しで増える。**ローリングの本体**。いまの休診日マスタから計算できる |
| **連休の長さと、その何日目か** | 3連休明けと1日休み明けでは戻り方が違う |

実際に出せることを確認した（2027年1月・年末年始休業 12/29→1/3 が効く月）。

```
  日 曜  営業  前日が休  翌日が休  連休の何日目
   1 金  休業     ○       ○        4
   2 土  休業     ○       ○        5
   3 日  休業     ○       −        6
   4 月  営業     ○       −        −     ← 6連休明け
   5 火  営業     −       −        −
```

**1月4日が「6連休明けの初日」と判定できる。** 追加のデータは要らず、
いまの休診日マスタと営業マスタだけで出る。
| 月内の位置（第何週・月初・月末） | 長期処方の集中、レセプト請求期 |
| 月・週番号 | 季節性（花粉・インフルエンザ）の代理 |
| 診療報酬改定月（4月・10月） | 問い合わせと変更が増える |

**調剤報酬の加算項目（★最優先・追加負担ゼロ）**

**算定した項目はレセコンに必ず残っている。** 日誌に正の字を書く必要がなく、
日次で件数を取り出せれば、それがそのまま工数の代理指標になる。
どれも「手のかかる調剤をした」という事実に対して算定されるものなので、
枚数では見えない忙しさを直接表す。

| 加算 | 何の手間か | 数え方 | 作業量との関係 |
|---|---|---|---|
| **一包化加算** | 分包機での一包化と鑑査 | **1処方箋につき1回** | **比例しない**。下記 |
| **計量混合調剤加算** | 軟膏・水剤・散剤の混合 | **混ぜた回数だけ** | 比例する |
| **自家製剤加算** | 錠剤の粉砕・分割、剤形の加工 | **1処方に複数取れる**（剤ごと） | 比例する |
| **重複投薬・相互作用等防止加算** | 疑義照会して処方変更に至った | 算定回数 | 照会1件ぶん |

**一包化だけ性質が違う。** 計量混合と自家製剤は作業回数がそのまま件数になるので、
件数が工数に直結する。一包化は1処方箋につき1回しか算定できないので、
**14日分の一包化と90日分の一包化が同じ「1」**になる。件数だけでは工数が分からない。

一包化の工数は投与日数で決まるので、**件数と併せて「一包化した処方の投与日数の合計」**
を取る。算定点数が日数の区分で変わる仕組みなら、点数から逆算してもよい。

**重複投薬・相互作用等防止加算は「疑義照会の下限値」として使える。**
照会しても変更に至らなければ算定されないので、実際の照会件数はこれより多い。
それでも傾向は追えるので、日誌に照会件数を書く前に、まずこちらで足りるか見る。

同じ理屈で**追加負担なしに取れる**もの（効きそうな順）。

| 加算・算定項目 | 何を表すか |
|---|---|
| 麻薬管理指導加算 | 手続きの重い調剤 |
| 特定薬剤管理指導加算（ハイリスク薬） | 指導に時間がかかる |
| 乳幼児服薬指導加算 | 小児。説明が長い |
| 在宅患者訪問薬剤管理指導料 | 在宅件数。別枠の工数 |
| 外来服薬支援料 / 服薬情報等提供料 | 持参薬整理・トレーシングレポート。まとまった時間を食う |
| 吸入薬指導加算 / 調剤後薬剤管理指導料 | 対面指導の時間 |
| 内服薬の**剤数** | 調剤料は剤数で決まる。剤数は手間にほぼ比例する |

**日誌に足すもの（レセコンから採れない場合のみ）**

| 特徴量 | なぜ効くか | 負担 |
|---|---|---|
| 疑義照会の件数（総数） | 加算に至らなかった照会も拾える | 正の字1つ |
| 新患の件数 | 初回は指導も入力も時間がかかる | 正の字1つ |
| 待ち時間のピーク（体感で可） | 人手が足りたかの直接の手応え | 3段階で十分 |

**レセコンから採れる（抽出の仕組みが要る）**

| 特徴量 | なぜ効くか |
|---|---|
| **処方日数の分布**（7/14/28/30/56/90日の件数） | **最大日数だけでは足りない。**N日後の再来を積み上げれば、定期患者の来局予測がそのまま作れる。ここが本丸 |
| 医師ごとの処方箋枚数 | 医師によって発行数が違う。「医師数」を「医師の顔ぶれ」に精緻化できる |
| 再来／新患の別 | 上と同じ |
| 後発品変更の有無 | 説明と入力の手間 |
| 受付時刻の分布 | 時間帯別の人繰りに直結 |

**店舗の静的属性（一度入れれば済む）**

| 特徴量 | なぜ効くか |
|---|---|
| 最寄り駅からの徒歩分 | 来局のしやすさ |
| 前面道路・立地区分（駅前／住宅地／병院前） | 客層の違い |
| 近隣の医療機関数 | 門前か面分業か |
| 座席数・作業台数 | **収容上限の根拠**（すでに店舗マスタにある） |

**外部データ（無料で取れる）**

| 特徴量 | 出どころ |
|---|---|
| 気温・降水量・降雪 | 気象庁の過去データ（CSV 配布） |
| 天気予報 | 気象庁の予報 API |
| 学校の長期休暇期間 | 自治体の学事暦（小児科があれば効く） |

### C. 効きそうだが、いまは取りにくいもの

- 近隣のイベント（学会・催事）
- 感染症の流行状況（定点報告は週次・地域単位で遅れる）
- 競合店の状況

## 3. 収集の器（設計）

### 3.1 日次実績（`日次実績` シート）— 学習データの1行

**店舗 × 日** で1行。これが積み上がったものが学習データになる。

| 列 | 内容 | 出どころ |
|---|---|---|
| 店舗ID | | |
| 日付 | | |
| 処方箋枚数 | 実績 | 日誌 |
| **一包化加算 件数** | 実績 | **レセコン** |
| **一包化 投与日数（合計）** | 実績 | **レセコン**。件数だけでは工数が出ない |
| **計量混合調剤加算 件数** | 実績 | **レセコン** |
| **自家製剤加算 件数** | 実績 | **レセコン** |
| **重複投薬・相互作用等防止加算 件数** | 実績 | **レセコン** |
| 麻薬管理指導加算 件数 | 実績 | レセコン |
| 在宅患者訪問薬剤管理指導料 件数 | 実績 | レセコン |
| 内服薬 剤数（合計） | 実績 | レセコン |
| 新患件数 | 実績 | レセコン／日誌 |
| 疑義照会件数（総数） | 実績 | 日誌 |
| 室温 / 湿度 | 実績 | 湿度計 |
| 外気温 / 降水量 | 実績 | 気象庁 |
| 予約数 / 予約枠数 | 実績 | 予約システム |
| 待ち時間ピーク | 3段階 | 体感 |
| 薬剤師 出勤数 / 事務 出勤数 | 実績 | シフト表から自動 |
| 医師数 | 実績 | シフト表から自動 |
| 備考 | 自由記入 | |

**暦から出る特徴量（曜日・祝日・連休・月内の位置）は保存しない。** 日付から計算できる
ものを保存すると、定義を変えたときに過去分と食い違う。

### 3.2 患者の来局台帳（`患者来局` シート）— **本命**

**次回来局日の予測は患者単位でしか作れない。** 残日数を追う必要があるため。

```
次回来局予定 = 今回の来局日 + 今回の処方最大日数 + 前回の残日数
前回の残日数 = 前回(来局日 + 処方日数) − 今回の来局日     （負なら 0）
```

早めに来た患者は手持ちが残るので、そのぶん次回が後ろへずれる。
**集計値ではこれが表せない。**

| 患者 | 来局 | 処方 | 残 | 次回予定 |
|---|---|---|---|---|
| A | 10/01 | 28日 | 0 | 10/29 |
| A | 10/29 | 28日 | 0 | 11/26 |
| B | 10/24 | 28日 | **5** | **11/26** ← 5日早く来ても次回はずれない |

日別の来局予測は、**その日に予定日が来る患者を数え上げるだけ**で出る。

| 列 | 内容 |
|---|---|
| 患者キー | 通し患者番号の**ハッシュ**。生の番号も氏名も持たない |
| 店舗ID | |
| 来局日 | |
| 処方最大日数 | その処方箋の内服の最長日数 |
| 残日数 | 前回から持ち越したぶん（計算） |
| 次回予定日 | 計算 |

**なぜ「最大」日数か**: 患者は次回受診まで足りるように処方される。内服の最長日数が
次回受診までの間隔にいちばん近い。頓服や外用は日数が短くても来局間隔を決めない。

### 個人情報の扱い

患者単位のデータを持つので、ここだけ性質が違う。

- **通し患者番号は、取り込みの境界でハッシュ化する。** 生の番号はシートに書かない。
  薬局に対応表がある以上、番号がそのまま乗れば持ち出された時点で氏名まで辿れる
- ソルトはスクリプトプロパティに置き、**控えを取る**（失うと過去と突き合わせられない）
- ハッシュ化は**シートが外へ出たとき**を守るもの。スクリプトを触れる人には無力で、
  **法令上の扱いは個人情報のまま**
- 氏名・生年月日・保険証番号・住所は受け取らない（`Intake.gs` が行ごと弾く）
- 目的は**来局日の予測のみ**。ほかの用途に使わない
- 保存期間を決める。予測に要るのは直近数回ぶんで、何年も持つ必要はない
- 仮名化しても個人情報保護法上の扱いが残る場合があるので、**運用前に確認すること**

### 3.3 処方日数の分布（`処方日数` シート）— 台帳が取れないときの代替

**店舗 × 日 × 処方日数** で1行。`日数` と `件数` の2列だけ。

患者台帳が取れない場合の代替。「N日後に何人戻るか」は積み上げられるが、
**残日数が追えない**ので、早めに来た患者のぶんが表せず、来局の山が実際より前に出る。

### 3.4 静的属性はマスタへ

| 属性 | 置き場所 |
|---|---|
| 最寄り駅・徒歩分・立地区分 | 店舗マスタ |
| 収容上限（座席・作業台） | 店舗マスタ（実装済み） |
| 診療科・平均処方箋枚数 | 医師マスタ |

## 4. 設計上の約束

**実績と予測を混ぜない。** 同じ列に実績値と予測値を入れない。予測は別シート（`予測`）に
持ち、`予測した日` を必ず記録する。混ぜると「その時点で何が分かっていたか」が
再現できなくなり、検証が成立しない。

**欠測を許す。** 天候が取れない日、日誌が空の日があっても行は作る。空欄と 0 は別物
なので、0 で埋めない。

**確定タイミングを持つ。** レセコン由来の値はあとから確定する。`取得日時` を持ち、
更新履歴を潰さない。

**粒度は日次に固定する。** 時間帯別が要るなら別シートにする。1つの表に粒度を混ぜない。

**店舗IDと日付が主キー。** 店舗が増えても壊れない形にしておく。

## 5. 進め方の提案

いまのシフト表から**ただで取れるもの**が既にある。まずそこから。

1. **シフト表から日次実績へ自動転記** — 薬剤師出勤数・事務出勤数・医師数は
   この画面が持っている。書き出すだけ
2. **暦の特徴量を計算で出す** — 前日/翌日が休診か、連休の何日目か。休診日マスタが
   あるので今日から出せる
3. **加算の件数を日次で溜め始める** — 一包化・計量混合・自家製剤・重複投薬。
   レセコンから日次で出せるなら追加負担ゼロ。出せなくても、
   **管理帳簿に項目を足して打ち込めば予測には使える**（項目が4つ増えるだけ）。
   一包化は件数に加えて投与日数も要る
4. **気象庁データの取り込み** — 過去データは CSV で配布されている。日次で結合するだけ
5. **患者の来局台帳** — 仮名化した患者キーと処方最大日数。**次回来局日の予測はここから**。
   レセコンからの抽出方法と、個人情報の扱いが決まってから

**1〜2 は今すぐできる。** モデルが無くても、この2つを溜め始めておけば、
半年後には曜日・連休・医師数の効果が見える程度のデータにはなる。

## 6. まだ決まっていないこと

- レセコンから日次で出せるか。出せなければ管理帳簿に項目を足して手で打つ
  （予測には使える。入力が続くかが課題）
- 予約システムの連携方法
- 日誌の入力を誰がいつ行うか（負担が続かないと欠測だらけになる）
- 目的変数を枚数から工数へ進めるか、進めるならどう計測するか
