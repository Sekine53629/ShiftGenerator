数理モデルと突き合わせた記録。元ファイルは実名を含むため `*.xlsx` `*.pdf` は
`.gitignore` 済み。ここには氏名・店名を書かない。

読み取りは zip + XML の直読み。**ふりがな（`rPh`）を本文と一緒に読むと `休` が `休ヤス` になる**ので、

## 1. シート構成（月ごとに行位置が動く）

1 年のあいだに様式が 3 回変わっている。読むときは 3 通りを見分ける必要がある。

| 様式 | 使われた月 | 医師の情報 | 記号 |
|---|---|---|---|
| A | R7.9・R7.11、R8.1〜R8.8 | 日付行が2本、その間に医師名 | `○` `●` `▲` |
| B | R7.12 | A列に「医師数」の**数値行** | `早` `遅半` `遅` |
| C | R7.10 | **なし** | `早` `遅半` `遅` |

休みの記号も `休` → `公休`、`希` → `希休` → `希望休` と揺れる。
判定は先頭1文字（`公` `希` `有` `夏`）か、`早`／`遅` で始まるか、で行う。
`○○` のように地名を書いた出張の記入もあり、これは出勤だが店には居ない。

| ブロック | 内容 |
|---|---|
| 1行目 | 表題 `R8.8月　土日公休10回　祝日1回　休みのトータル11回` |
| 日付行① | 日付シリアル（**再計算されておらず値は当てにならない**。表題の年月と曜日行が正） |
| 曜日行 | 日〜土 |
| 医師欄 | 4〜6行。氏名列は空 |
| 日付行② | 同じ日付の繰り返し |
| 薬剤師（社員） | 氏名列に `氏名(週4)` `氏名(月火金土18時)` のような但し書き |
| 派遣 | 氏名列 `<派遣会社名>(派遣)` / `単発`。**セル自体に `●氏名` と書く。1日複数人、続き行にも載る** |
| 事務 | 派遣ブロックの下 |
| 注記 | 開局時間、休憩割り、発注担当など |

行番号は月ごとに違う。**日付行①②の間＝医師欄、最後の派遣行より下＝事務**、という相対位置で取る。

## 2. シフト記号は3種類だけ

凡例（全月共通）:

- `○` 早　10:00〜19:00
- `●` 遅半 10:30〜19:30
- `▲` 遅　11:00〜20:00

出現数は `▲` が最多で全体の約半分。`○` と `●` がそれに続く。

休みの記号:

| 記号 | 意味 | 備考 |
|---|---|---|
| `休` → `公休` | 公休 | **1〜2月は `休`、3月から `公休` に表記変更** |
| `希休` | 希望休 | 公休枠として機能 |
| `有休` | 有給 | 公休枠の外 |

`▲健診` `○出張` `○移→他店` のように記号＋補記のセルがある。**判定は先頭1文字で行う**。
`●支援不可` のような注記セルもあるので、派遣の人数を数えるときは除外が要る。

## 3. 公休ノルマの算出ルール（裏取り済み）

8月の表題に運用側が書いている:

> 土日公休10回　祝日1回　休みのトータル11回

これはプロトタイプの計算式（**土 + 日 + 公休加算の祝日、重複は1日**）と一致する。

8か月・欠けの無い常勤 69 人分で照合した結果、**57人（83%）がノルマぴったり**。
外れた12人は全員 **+1〜+5 のプラス側**（時短・週4契約・入退社月）で、**マイナスは1件も無い**。

→ 「公休はビタビタ、足りない分は有休・夏休」という運用は実データで裏が取れた。

臨時休業（3月に3日間の改装工事）は **全員 `公休` で埋められ、ノルマに算入されている**。
一方、正月三が日（1/1〜1/3）は **セルが空欄**で、ノルマからも外れている。運用が揺れている。

私が置いた曜日別下限（木5）が原因であって、現場の需要ではない。

## 8. 曜日別下限が生んでいた「木曜の不足」

実測と突き合わせる前、プロトタイプの自動生成は医師パターン13種すべてで木曜だけが
不足していた。原因を切り分けた記録を残す。答えは**曜日別下限が実測と合っていなかった**こと。

必要人数は「曜日別下限」と「医師数から引いた人数」の大きいほうを採る。
どちらが勝っているかを曜日ごとに並べると、木曜だけが2つの条件に重なっていた。

| 曜日 | 下限 | 医師 | 目安 | 決めたのは | 出られる人 |
|---|---|---|---|---|---|
| 日 | 2 | 3.0 | 3.0 | 医師 | 6人 |
| 月 | 6 | 3.8 | 6.0 | 下限 (+2.2) | 7人 |
| 火 | 5 | 4.0 | 5.0 | 下限 (+1.0) | 7人 |
| 水 | 3 | 4.0 | 4.0 | 医師 | 6人 |
| 木 | 5 | 3.0 | 5.0 | **下限 (+2.0)** | **6人** |
| 金 | 6 | 5.0 | 6.0 | 下限 (+1.0) | 7人 |
| 土 | 3 | 3.0 | 3.0 | 同値 | 7人 |

水曜も「出られる人が6人」だが、下限3が医師4診より低いので下限が効いていない。
必要人数は医師側の4人で決まり、6人から4人なら余裕がある。

そして**人手が原因ではなかった**。日水木が出られない人を全曜日可にしても木曜の不足は
4人日のまま変わらない。効いたのは連勤上限だった。

木曜に集まる仕組みは連勤の玉突きである。日曜は下限2なので大半が休み、その明けの月曜は
下限6でほぼ全員が要る。そこから連勤が始まり、上限3日だと月火水で打ち止めになって
木曜が強制的に休みになる。連勤上限3日のとき、水曜で上限に当たって終わる連勤が8回、
木曜の休み14回のうち8回がその直後だった。日曜の下限を2→5に上げて起点を1日ずらすと、
上限いっぱいで終わる曜日が水曜→火曜へ移り、木曜の強制休みは8回→2回に減った。

```
  そのまま（連勤3）                    6人日   うち木曜 4人日
  出られない曜日を解除                  6人日   うち木曜 4人日   ← 効かない
  水曜（木の前日）の下限を下げる         6人日   うち木曜 4人日   ← 効かない
  連勤上限を4に                        3人日   うち木曜 1人日
  下限を全曜日4に均す                   1人日   うち木曜 1人日
  曜日別下限を撤廃                     0人日   うち木曜 0人日
```

なお下限の合計は月134人日、実際に置けた延べ出勤は約143人日で、**総量では9人日余っている**。
残る不足には、週全体を見て入れ替えない貪欲な配置の弱さも混ざっている。

これを受けて2つ変えた。

1. 連続出勤の上限の既定を **3日 → 4日**（実測で4連勤は18.7%）
2. **曜日別下限を「医師が入っていない日の当て板」に格下げ**した
   （`rules.floorOnlyWhenNoDoctor`、既定 on）

2 の根拠は立地である。この薬局は建物の7階にあり、面薬局としての立地がよくない。
**休診日に処方箋の需要はほとんど無く、営業は診療に合わせている。** 祝日も病院が
開くので、祝日は休みではなく営業日になる。需要は曜日ではなく診療数で決まる。

実測もそうだった。8か月で医師0人の日は正月三が日の3日だけで、その3日は店も
閉まっている。祝日（成人の日・建国記念の日など）はすべて医師・薬剤師とも通常どおり
出ていた。休診日に薬局だけ開ける、という日は1日も無い。

`rules.weekdayFloor` は3択にした。門前ではない店のために戻せるようにしてある。

| 値 | 動き |
|---|---|
| `off`（既定） | 必要人数は診療数だけで決める |
| `noDoctor` | 医師欄が空の日だけ曜日別下限を当て板に使う |
| `always` | 診療数から引いた人数と曜日別下限の大きいほう（面薬局向け） |

`off` のとき、医師欄が空の日は必要人数マスタの `0診` の行が当て板になる。
実物の注記に「薬剤師1名で開局」とあるので、その行は1名にした。
医師欄の入れ忘れに気づけるよう、空の日があると警告を出す。

この2つを入れたあと、医師パターン13種 × 派遣3水準の39通りで、
**派遣なしでも下限割れは全通りゼロ**になった。公休ノルマも全通りちょうど。

## 10. 事務の減りかた

薬剤師の話の裏で、**事務が半減している**。診療数が伸びている期間とちょうど重なる。

```
  年月    在籍  延べ出勤  1日平均  医師平均  薬剤師/事務
  2025-09   3名     53人日    1.77     2.93      1.94
  2025-11   4名     62人日    2.07     3.13      1.85
  2025-12   4名     72人日    2.48     3.31      1.61
  2026-02   4名     67人日    2.39     3.61      1.69
  2026-03   4名     80人日    2.58     3.77      1.39
  2026-04   4名     80人日    2.67     3.70      1.70   ← 頂点
  2026-05   3名     52人日    1.68     4.16      2.46
  2026-06   3名     66人日    2.20     4.50      2.24
  2026-07   3名     53人日    1.71     4.45      2.96
  2026-08   2名     38人日    1.23     4.23      4.26   ← 半減
  2026-09   2名     38人日    1.27     4.23      4.25
```

在籍 **4名 → 2名**、延べ出勤 **80人日 → 38人日**。同じ期間に診療数は 3.70 → 4.23 診へ増え、
薬剤師は増員している。**薬剤師1人あたりが頼れる事務の数は 1.70 → 4.26 と 2.5 倍に薄まった。**

これが効くのは、この店の運用が事務と薬剤師を分けていないからである。シートの注記に

> ○早番は受付で処方入力、▲遅番はピッキング、午後から交代

とあるとおり、受付・入力は事務と薬剤師で分け合っている。**事務が薄いぶんは薬剤師が埋める。**
日単価は薬剤師 27,426円 に対し事務はそれより低いので、差額はそのまま損になる。

派遣が跳ねた月と事務が減った月も重なる。

```
  年月    事務  薬剤師の在籍  派遣
  2026-04  4名      7名        10人日
  2026-05  3名      7名         5人日
  2026-06  3名      6名        28人日
  2026-07  3名      6名        37人日
  2026-08  2名      7名        35人日   ← 薬剤師は戻ったのに派遣は高いまま
```

2026-08 は薬剤師の在籍が7名へ戻っているのに派遣が35人日ある。
**薬剤師の頭数だけでは説明がつかず、事務の不足が残っている。**

1日2.5人（2026年春の水準）へ戻すには、いまの 38人日/月 に対して
**+37人日/月 ＝ 事務2名の増員**が要る。

曜日別に見ても事務は 1.90〜2.20 人と平坦で、どこか特定の曜日だけ薄いのではない。
**全体が薄い。**

## 11. 出力ファイルの命名

PDF・xlsx とも実物の運用に合わせる。

```
  さくら薬局北口店R08.09月シフト.pdf
  {店舗名}R{和暦2桁}.{月2桁}月シフト.{拡張子}
```

和暦・月ともゼロ詰め2桁。ひな型は `CONFIG.EXPORT_NAME`、組み立ては
`Export.gs buildExportFileName_()`。店舗名は設定シートから取り、コードに書かない。
プロトタイプ側は `exportFileName_()` が同じ形を作る。

**和暦は令和固有の計算（西暦 − 2018）。** 元号が変わったら `CONFIG.WAREKI_BASE` を
直す必要があり、自動では追従できない。令和元年より前は例外にしてある。

## 12. 処方箋の増加予測について

**シフト表に処方箋枚数は入っていない。** いま予測に使えるのは診療数だけで、
上の推移がそのまま需要の代理指標になる。

処方箋枚数そのものを予測するには、あと1つで足りる。

- **日別の処方箋枚数**（管理帳簿に1列足すだけ）

これがあれば「診療1つあたり何枚か」の換算係数が出て、上の診療数の系列を
そのまま処方箋枚数の見込みに変換できる。いまは係数が無いので、
「診療数が1年で1.4倍になった」以上のことは言えない。

さらに精度を上げるための特徴量は `docs/FEATURE-COLLECTION.md` に、
レセコン側から取る項目は `docs/RECEIPT-API.md` にまとめてある。
