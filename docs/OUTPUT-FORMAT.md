# 出力フォーマット（実物の計測）

PDF・xlsx の出力を実物に寄せるための計測記録。対象は R8.8月のブック。
Excel も VBA も使わず、`.xlsx` の中の XML を直接読んだ（`xl/styles.xml`,
`xl/worksheets/sheet1.xml`, `xl/theme/theme1.xml`）。

Google スプレッドシートへ取り込んだあとを測ると条件付き書式などが落ちるので、
**原本の XML を読むのが正しい。** `tools/ExportFormatProfile.bas`（VBA）も
同じ目的の道具だが、Excel を開く必要がある。XML 直読みなら要らない。

## 1. 列幅（文字数単位）

| 列 | 幅 | 用途 |
|---|---|---|
| A | 12.40 | 氏名 |
| B〜AG | 5.50 | 日付（32列） |
| AH〜AK | 6.60 | 集計（**4列**） |
| AL 以降 | 9（既定） | 未使用 |

集計列は **4列**。仕様書 §5.4 は6列としているが、実物は4列
（`docs/REAL-SHEET-FINDINGS.md` に既出）。

## 2.5 年月の表記は、表題とファイル名で違う

```
  シートの表題（A1）   R8.8月     ← ゼロ詰めしない
  ファイル名           R08.08月   ← ゼロ詰めする
```

同じ月を指すのに規則が違う。実物がそうなっているので、そのまま写す。

D1（A1 の右、日付列の上）に公休の内訳を書く。

```
  土日公休10回　祝日1回　休みのトータル11回
```

R8.8月から始まった書き方で、R8.9月にもある。それ以前の月には無い。
区切りは全角空白。**店名はシートに入っていない**（ファイル名だけ）。

## 4. 色

`xl/theme/theme1.xml` を解決した実値。

| 色 | 使いどころ |
|---|---|
| `#bdd7ee` | **土曜**（accent5 の tint 0.6） |
| `#ff6d6d` | **日曜と祝日**（同じ色） |
| `#d0cece` | **「ここは入力しない」の印**（下記3用途） |
| `#a9d18e` | **薬品発注担当**（凡例の見本セルは 行37列2） |
| `#ffc000` | **備品発注日**（凡例の見本セルは 行40列2） |
| `#ffff00` | その場かぎりの目印（凡例に無い） |
| `#ff0000` | その場かぎりの目印（凡例に無い） |

**祝日に専用の色は無い。日曜と同じ `#ff6d6d`。**
条件付き書式は使っておらず、すべて直接塗ってある。

### 色の印は記号と別の層

R8.8月で本文セルに付いていた色を数えると、**定義された印は2つ**だった。

```
  #a9d18e  24件  すべて ○(早番) の日。土曜と祝日の前日には無い
                 凡例「薬品発注担当（土曜日と祝日の前日は発注作業なし）」
  #ffc000   3件  すべて水曜。凡例「備品発注日（週1）」
  #ffff00   3件  凡例に無い。有休や「白衣持参」の注記に付いていた
  #ff0000   1件  凡例に無い
```

**色は記号を消さずに背景だけを塗る。** 同じセルに「▲かつ薬品発注担当」が同居する。
プロトタイプも同じ形にした（`DB.marks` と `mark:` 接頭辞のキー）。

凡例は表の下に見本セル（色だけのセル）と説明文を並べる形。
**何色が何を指すかを紙に書いておかないと、配られた人には伝わらない。**

### 灰色 `#d0cece` の3つの用途

同じ灰色が、意味の違う3か所に使われている。共通するのは
**「ここは入力しない／できない」** という意味。

1. **月の日数に足りない余り列**
   日付列は B〜AG の32列を常に確保するので、31日の月では AG が余る。
2. **出られない曜日**（個人ごと）
   R8.8月では、A列に `(月火金土18時)` と書かれた人の **日・水・木** が
   灰色で潰されていた。31日中13日。`availDow` の視覚表現にあたる。
3. **在籍していない期間**（行まるごと）
   同じ月に、31日すべてが灰色の行が1つあった。退職・休職で行だけ残っている形。

2 は「空欄」と「そもそも出られない」を見分けるために要る。プロトタイプは
`availDow` を配置には使っていたが画面に出しておらず、空欄と区別が付かなかった。
実物に合わせて灰色にした（`naDay_()`。押せなくはしない —
管理者が事情を承知で入れることはあり、入れればルール違反として表の下に出る）。

3 は扱いが違う。プロトタイプは `inService` で**行ごと消す**。実物は行を残して灰色にする。
月の途中で入退社した場合にどちらが読みやすいかは要判断。

| | 実物 | プロトタイプ | 備考 |
|---|---|---|---|
| 土曜 | `#bdd7ee` | `#b8c6da` | 近いが別の色 |

増える」ことが表から読み取れなくなるので、区別する側にも理はある。

## 7.5 勤務時間は営業時間を覆っているか

記号ごとに勤務時間が30分ずつずれている。**頭数が足りていても、時間帯によっては
薄くなる。** 実物は 開局10:00〜20:00 に対して

```
  ○ 早番  10:00〜19:00     開局を覆う
  ● 遅半  10:30〜19:30
  ▲ 遅番  11:00〜20:00     閉局を覆う
```

つまり **早番が0人だと開局が無人、遅番が0人だと閉局が無人**になる。
30分でも締め作業ができない日は作れない。

`coverageOf_()` は、人が来た時刻と**帰った時刻の両方**を見て、いちばん薄い
時間帯の人数を返す。来た時刻だけ見ていたころは、遅半が19:30に上がったあとの
穴に気づけなかった。

自動生成は次の2つを守る。

- 開局を覆えるだけ早番を置く（`rules.minOnDuty`）
- **閉局まで残る人を必ず1人は空けておく。** 早番と遅半で全員を使い切らない

それでも薄い日は表の下に出す。たとえば遅半を2人にすると、閉局前の30分が
1人になる日が出る。これは頭数では見えない。

## 8. 出力の経路（実装したもの）

出力ボタンは2つ。**どちらも同じ表を出す。**画面のセルをそのまま読み、
`printMetrics_()` で**印刷したときの色**にしてから写す。画面の色（店舗色・
暗い画面）を写すと、PDF と Excel で別の色になる。

| ボタン | 経路 | 出るもの |
|---|---|---|
| PDF | `window.print()` → ブラウザの「PDF に保存」 | 1枚に収まった A4横 |
| スプレッドシート | `google.script.run.apiExportToSheet(model)` | ブックに**新しいシート**を挿す |

`sheetModel_()` が両方の入力になる。値・色・結合・数値かどうかを持った格子で、
これを `buildXlsx_()`（ブラウザ側）と `exportModelToSheet_()`（サーバ側）が読む。

### 出力の色（1.15.0）

Excel と PDF の背景色・見出しの文字色は、**「出力の色」タブで変えられる**（`DB.outColors`）。
項目と既定の色は `OUT_COLOR_ITEMS` の1か所にあり、Excel（`buildTemplateXlsx_`）と PDF（`buildPrintSheet_`）は
どちらも `outColorsOf_()` を通して同じ色を読む。画面のシフトエディタの色は変えない。

| 区分 | 項目 | 既定 |
|---|---|---|
| 日付・曜日 | 土曜 / 日曜 / 祝日 / 月の外・仕切り・出られない日 | `#BDD7EE` / `#FF6D6D` / `#FFC000` / `#D0CECE` |
| 薬剤師 | 氏名の欄 / シフトの欄 | `#E2EFDA` / 塗らない |
| 派遣 | 氏名の欄 / シフトの欄 | `#DDEBF7` / `#DDEBF7` |
| 事務 | 氏名の欄 / シフトの欄 | `#FCE4D6` / `#FCE4D6` |
| 集計の見出し（文字） | ○早番 / ▲遅番 / ●遅半 | `#FF0000` / `#4472C4` / `#70AD47` |

- 保存した値が空文字なら「塗らない」（文字色なら黒）。値が無い・読めないときは既定
- 色の印（備考マスタ）はこれより優先。祝日が日曜に重なれば日曜の色
- データ書き出し・取り込みに `outColors` として入る。古いデータには無いので、`migrateDb_` が空で用意する（全部既定）

### PDF の表（1.14.0）

**PDF も Excel と同じ様式・同じ色で刷る。**画面の表を縮めて刷るのをやめ、`templateModel_()` から
`buildPrintSheet_()` が印刷専用の表（`#printSheet`）を組む。印刷のときはこの表だけを出す。

- 値は画面の集計をそのまま刷る（紙に数式は無い）。数え方は画面と同じ関数（`rowAggOf_` / `dayAggOf_`）
- **余白は上下左右とも 8mm**（`@page`）。表の幅は 297 − 16 = 281mm ちょうどで、列の幅は Excel の列幅の比。
  以前は左 0.6cm・右 0 の余白で画面の表を倍率で縮めていて、表が右に寄り、右端の集計が紙からはみ出していた
- 行の高さは行数から決める（3.4〜6mm）。下限まで詰めても入らないときだけ全体を縮める
- 組み直すのは印刷の直前（PDF ボタンと Ctrl+P の `beforeprint`）

### PDF の保存名

ブラウザは `document.title` から保存名を作る。刷るあいだだけ差し替えて、
`afterprint` で戻す（戻さないと、次に保存する名前まで変わる）。
自前で PDF を組む道もあるが、日本語の埋め込みフォントで数MBになるので取らない。

### スプレッドシートへの出力

**新しいシートを挿す。既にある表は触らない。**同じ月を2回出すと `(2)` が付く。
配ったあとに作り直すことがあり、上書きするとどちらを配ったか分からなくなる。

数式も名前付き範囲も入れない、値と見た目だけの動かないシートにする
（作成用の `Setup.gs` / `SheetBuilder.gs` とは目的が違う）。

書き込みは範囲ごとに1回。行の高さだけは同じ値が続くところをまとめる
（43行 → 4回）。実測で1か月ぶんが 38 往復。

**画面から来た文字列は `cellSafe_()` を必ず通す。** `=IMPORTRANGE(...)` は
シートに置いた瞬間に数式になり、他所のデータを引かせられる。

まだ入っていないもの:

- **誰が出したかの検証。**`Auth.gs` は揃っているが、社員マスタ
  （email / 権限 / 担当店舗）の読み手がまだ無い。保存 API も同じ状態。
- 印刷設定。Sheets の API では設定できないので、シート側は既定のまま。
  紙は PDF ボタンから出す。

### Google に繋がっていないとき

単体の HTML として開いているときは `google.script.run` が無い。
そのときだけ `.xlsx` で保存する（無圧縮 zip + XML を自前で組む）。
スプレッドシートにそのまま読み込める。

**.xlsx は見本の様式で組む**（1.13.0）。画面の格子を写すのではなく、データから
`templateModel_()` → `buildTemplateXlsx_()` で組む（Google 側の書き出しは従来どおり `sheetModel_()`）。
寸法と色は見本（R8.8月シフト.xlsx）を Excel で測った値で、`XL_TPL` にまとめてある。

| 行・列 | 中身 |
|---|---|
| 1行目 | 表題（A1:C1、28pt）・公休告知（D1 から右へはみ出す）・店名（R1） |
| 2・3行目 | 日付（Arial 13）・曜日（ＭＳ Ｐゴシック）。土曜 `#BDD7EE`・日曜 `#FF6D6D`・祝日 `#FFC000`（日曜に重なれば赤）・月の外 `#D0CECE` |
| 医師の行 | 医師名欄の行数だけ |
| 日付の再掲 | 右に集計の見出し（○早番 赤・▲遅番 青・●遅半 緑） |
| 社員の行 | 薬剤師 → 派遣 → 事務。帯は入れない（見本と同じ）。薬剤師は氏名だけ `#E2EFDA`、派遣は行ごと `#DDEBF7`、事務は行ごと `#FCE4D6`（R8.9月・10月の実物の塗り方）。印の色・出られない日の灰はそれより先に塗る |
| 備考 | 小さい字（8pt）、上だけ罫線（見本の「銀行」の行） |
| 下の集計 | 医師数(診)・薬剤師出勤数・事務員出勤数・過不足 |
| 凡例・注記 | 凡例は A、注記は F から横に並べる。色の凡例は B に色・C に意味 |
| 列 | A 氏名 12.4 / B〜AF 日 5.5 / AG 灰色の仕切り / AH〜 集計 6.58。倍率 70%、A4 横で1枚 |

**集計は数式で入れる。**配ったあとに Excel で記号を直しても集計が付いてくる。

| 場所 | 式 |
|---|---|
| 右の集計列（社員の行）公休・有休・○早番・▲遅番・●遅半 | `COUNTIF(B行:AF行, 記号)`。記号が2つ以上なら `SUMPRODUCT(COUNTIF(…,{…}))`。記号の一覧は画面の集計と同じ `AGG_COLS.syms` |
| 右の集計列 ◯診出勤 | 医師数の行が設定（既定 5）以上の日の出勤。`COUNTIFS` を出勤記号ごとに足す |
| 下の 医師数(診) | `COUNTA(医師の行)` |
| 下の 薬剤師出勤数・事務員出勤数 | 出勤記号の `COUNTIF` の合計（薬剤師は派遣を含む） |
| 下の 過不足 | 薬剤師出勤数 − 必要人数。必要人数は医師数から仕事率モデルの式（`staffNeedOf_` と同じ。設定の2点を式に書き込む）。足りない日は赤 |

- **過不足に年末年始のローリングは入らない。**医師数だけの式なので、ローリングの日は画面とずれる。
- `MATCH` に配列を渡す書き方は使わない。Google スプレッドシートは黙って1つ目しか見ない。
- 医師の来ない日は「空のセルを参照」の緑の印が出るので、`ignoredErrors` で消す。
- 画面から来た文字列は、`=` で始まっても文字列（inlineStr）で入る。数式になるのは集計だけ。
- 確かめ方: 自動生成した表をこの形で書き出して Excel で開き、集計 214 か所の結果が画面の集計と
  すべて一致することを見た（R8.11月・社員15人）。式と位置は `prototype/tests/export.test.js`。
