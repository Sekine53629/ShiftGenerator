# 実物のシフト表と移植仕様書の差分

運用中のシフト表（PDF）を読んで見つかった、`GAS-PORTING-SPEC.md` に書かれていない
／書かれている内容と食い違う点をまとめる。仕様書は VBA のソースから起こしたもので、
**実際に印刷されている表とは形が違う**箇所があった。

- 調査日: 2026-09-03
- 対象: 運用中の月次シフト表 1 か月分（PDF）
- **この文書に実名は書かない。**氏名・医師名・派遣スタッフ名・面談日程はすべて伏せる
  （Tier 3「実名をコードに書かない」／リポジトリは public）

各項目の「対応」は現時点の判断。★ が付いたものは**利用者の判断が要る**。

---

## 1. 集計列が実物は4列、仕様書は6列 ★

| | 列 |
|---|---|
| 実物 | `休` / `○早番` / `▲遅番` / `●遅半` の **4列** |
| 仕様書 §5.4 | `AH 公休` / `AI 有休` / `AJ ○早番` / `AK ▲遅番` / `AL ●遅半` / `AM 5診出勤` の **6列** |

実物の `休` は公休・希休・有休・夏休をひとまとめに数えた1列。
仕様書はこれを「ノルマ対象（AH）」と「ノルマ外（AI）」に割っている。
`5診出勤` に相当する列は実物には無い。

**対応**: 仕様書の6列で生成した（仕様書が契約なので）。6列は実物の情報を含む上位集合で、
`AH + AI` が実物の `休` と一致する。ただし**見た目は実物と変わる**。
実物どおりの4列にしたいなら `SHEET_BUILD.AGG_HEADS` と `writeAggregateColumns_()` を変える。

---

## 2. 集計行（医師数(診) / 薬剤師出勤数 / 過不足）が印刷に出ていない ★

仕様書 §3.1 では 31〜33 行にこの3行がある前提だが、実物の印刷には見当たらない。
非表示にしているのか、そもそも使っていないのかは PDF からは判別できない。

**この3行は自動作成の中核**で、`過不足` の元になる `required = 医師数 + reqPlus` が
ここから来る。無いと `Layout.resolveLayout()` が集計行を見つけられず、自動作成が動かない。

**対応**: 生成する。使わないなら行を非表示にすればよく、削ってはいけない。

---

## 3. 和暦が実際に使われている

実物の見出しは「R8.9月」。仕様書 §5.2 は「Sheets に和暦のカスタム書式が無いので西暦にする」
としているが、実物は和暦が主役だった。

**対応**: 年月セル（A列）は西暦の日付で持ち、見出し（D列）に和暦を数式で組んだ。

```
="R"&(YEAR(A1)-2018)&"."&MONTH(A1)&"月"
```

**`-2018` は令和固有**なので、元号が変わったらこの数式を直す必要がある。
自動追従はできない（README にも記載）。

---

## 4. 医師名欄の下に「日ごとの担当者」を書く行がある

医師名欄と再掲日付行のあいだに、日ごとに担当者名が入る行があった
（薬品発注担当・備品発注日）。仕様書 §3.1 はここを「12行 空行」としか書いていない。

**対応**: 生成時に1行確保し、`freeRow`（自由行）と名付けた。
マクロは読み書きしない。既存ブックから移す場合もこの行を消さないこと。

---

## 5. ⚠ 派遣行のセルが「記号＋氏名」の複合テキストになっている

派遣スタッフの行は、セルに記号だけでなく `▲` や `●` に続けて氏名が書かれている。
勤務時間帯（`↑15-20` のような）を別の行に添える使い方もされていた。

これは仕様書 §4.4「既存分類」の規則に噛み合わない。

```
記号 ○ ◯ ● ▲ のいずれか → ST_FWORK
それ以外の非空文字        → ST_FOFF （希休・有休・公休など）
```

**「▲＋氏名」は完全一致しないので `ST_FOFF`＝休みとして数えられる。**
同じ理由で、薬剤師出勤数の `COUNTIF(...,"▲")` にも入らない。

実害は限定的（該当行は `手動` ルールにすれば配置対象から外れる）が、
**その行を薬剤師の頭数に入れたいなら数え漏れる**。

**対応**: 未定 ★
考えられる手は3つ。
1. 派遣行は `手動` ルールにし、頭数にも入れない（現状の運用に近い）
2. 記号を別セルに分け、氏名は隣の行／列に書く
3. 分類と集計を「先頭1文字が記号なら出勤」に緩める
   → **VBA 版と結果が変わる**ので、移植が終わるまでは採らない

---

## 6. 氏名に勤務条件が埋め込まれている

シフト表の A 列には `(週4)` や `(月火金土18時)` のような但し書きが付いた氏名がある。

自動作成設定シートとの照合キーは**氏名の完全一致**（仕様書 §3.3）。
但し書きまで含めて一致していないとマスタに当たらず、「設定未登録」の警告になる。

**対応**: 生成時は自動作成設定の氏名をそのまま A 列に書くので、
**マスタ側を実物の表記に合わせる**のが正しい。設定チェックで不一致を出す。

---

## 7. 印刷範囲が「過不足行」より下まで及んでいる ★

実物の印刷には、表の下に凡例・休憩の決まり・医事メンバーの説明・面談日程の表が入っている。
仕様書 §7.3 の出力範囲は「年月・タイトル行 〜 過不足行 / A〜AM」なので、
**この下半分が切れる**。

**対応**: 未実装（PDF 出力はフェーズ7）。
`Export.getExportRange_()` の下端を「過不足行」ではなく
「シートの最終行」または利用者が指定した行にするか、決める必要がある。

---

## 8. 月の日数より列が多い（30日の月に31列）

日付列は `B`〜`AF` の 31 列に固定なので、30 日以下の月では末尾が翌月の日付になる。
仕様書は「月内判定は `Month(日付) === Month(対象月)`」とだけ書いていて、
**見た目の扱いには触れていない**。放っておくと翌月1日の列に書き込めてしまう。

**対応**: 条件付き書式で月外の列を灰色にした（入力欄・集計行まで含めて）。
エンジン側は従来どおり `inMonth` で弾く。

---

## 9. 条件付き書式から他シートを直接参照できない（Sheets の仕様）

土日・祝日の色分けで祝日マスタを見たいが、**条件付き書式のカスタム数式は
他シートを直接参照できない**。`INDIRECT` で包む必要がある。

直接書いてもエラーにはならず、静かに一度も一致しなくなる（§5.3 の `MATCH` と同じ質の罠）。

```
✗ =COUNTIF(祝日マスタ!$A:$A, B$2)>0
○ =COUNTIF(INDIRECT("祝日マスタ!$A:$A"), B$2)>0
```

**対応**: `INDIRECT` で実装済み。

---

## 10. 名前付き範囲は月ごとのシートには貼れない

名前付き範囲の名前はスプレッドシート全体で一意なので、
12 か月分のシートに同じ `シフト入力範囲` を付けることはできない。

**対応**: 月別シートには貼らない。`Layout` の計算解決を正としているので
名前が無くても自動作成は動く（仕様書 §5.5 の方針どおり）。
正典の `シフト` シートを作ったときだけ、利用者向けの目印として貼る。
